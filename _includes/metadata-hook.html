{%- comment -%} Clear the image loading placeholder when an image FAILS. Chirpy strips its `shimmer` (and `blur`) loading placeholder from an image's wrapper on the image's `load` event only. A broken image never fires `load` -- it fires `error` -- so its wrapper keeps running `animation: shimmer 1.3s infinite` forever. Visually that reads as the page perpetually loading or reloading itself, which is what it was mistaken for. This matters here more than upstream: ~2,700 imported posts carry 2002-2011 images, many externally hosted and steadily rotting, and tools/test.sh runs html-proofer with --disable-external, so a dead image URL is never caught at build time. Clearing on `error` makes a broken image degrade to a plain broken image instead of an endlessly pulsing block. Upstream fix would be an `error` listener alongside the `load` one in the theme's img-loading module; until that exists this hook is the least invasive place to do it, since metadata-hook.html is an empty placeholder the theme provides for exactly this kind of addition. {%- endcomment -%}
